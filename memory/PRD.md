# Parlance - Real-Time Chat Application PRD

## Overview
**Project Name:** Parlance
**Description:** A modern, scalable real-time chat platform (Slack-like)
**Tech Stack:** React 18 frontend + **Spring Boot 3.2 (Java 17) + PostgreSQL 15** backend
**Last Updated:** 2026-05-05

---

## Architecture

### Backend (`/app/springboot`)
- Spring Boot 3.2.3, Java 17
- Spring Data JPA + Hibernate with PostgreSQL 15 (database: `parlance`, user: `parlance`)
- Spring Security 6 with custom JwtAuthFilter + JwtAuthenticationEntryPoint
- Stateless JWT authentication (HS384) — access token (24h) + refresh token (7d). Tokens are set as httpOnly cookies AND returned in response body for WebSocket use.
- bcrypt password hashing, brute-force protection (5 failed attempts / 15 min lockout)
- Plain WebSocket handler at `/api/ws?token=<jwt>` (no STOMP)
- Jackson globally configured with `SNAKE_CASE` property naming to match the frontend's snake_case contract
- Runs directly under supervisor on port 8001 (no Python proxy)

### Frontend (`/app/frontend`)
- React 18 + React Router v6
- Tailwind CSS, shadcn/ui, Framer Motion, React Hot Toast
- AuthContext (login/register/refresh/logout) and ChatContext (WebSocket + REST)
- Plain WebSocket client at `${REACT_APP_BACKEND_URL}/api/ws?token=...`
- Dark / light theme toggle

### Database Schema (PG, auto-generated by JPA `ddl-auto=update`)
- `users`, `channels`, `channel_members`, `groups`, `group_members`
- `messages` (content, sender_id, room_type, room_id, reply_to, edited_at, deleted flag)
- `reactions`, `login_attempts`

## What's Been Implemented

### 2026-05-05 — Phase 1 (superseded)
- Initial build on Python FastAPI + MongoDB. Tests passed. Later rewritten.

### 2026-05-05 — Phase 2 Migration to Spring Boot + PostgreSQL
- Complete Spring Boot 3.2 rewrite: models, repositories, services, controllers, DTOs, security, WebSocket handler
- PostgreSQL 15 installed, database/role provisioned
- Maven build produces `parlance-0.0.1-SNAPSHOT.jar`

### 2026-05-05 — Phase 2 Bring-up & Fixes
- Supervisor backend program replaced: now runs `java -jar` directly on port 8001 (Python proxy removed)
- Added `spring.jackson.property-naming-strategy=SNAKE_CASE` so all REST JSON is snake_case (matches existing frontend)
- **CORS fix:** switched from `setAllowedOrigins` to `setAllowedOriginPatterns` with trimmed list, and added wildcard entries for both `*.preview.emergentagent.com` and `*.preview.emergentcf.cloud` (Emergent ingress rewrites the browser Origin to an internal cluster hostname). Without this the public URL returned 403 "Invalid CORS request".
- Added `JwtAuthenticationEntryPoint` → returns 401 JSON (not 403 empty) for unauthenticated/invalid-token requests
- Added `GlobalExceptionHandler` (@ControllerAdvice) → maps `ResponseStatusException` to proper HTTP status + JSON body
- Duplicate email / duplicate channel name now return 409 Conflict (was 400 / 401)

### Auth Endpoints
- `POST /api/auth/register` (201)
- `POST /api/auth/login` (200 / 401 on bad creds / 429 on brute-force lockout)
- `GET  /api/auth/me` (200 / 401 without token)
- `POST /api/auth/logout` (200)
- `POST /api/auth/refresh` (200)

### Channels / Groups / DMs / Messages / Users / Presence
All routes under `/api/*` as listed in iteration_3 test report. 20/20 backend pytest passed through the public URL.

### Real-time (WebSocket)
- `wss://<host>/api/ws?token=<access_token>`
- Events: `connected`, `message`, `message_edited`, `message_deleted`, `reaction`, `typing`, `presence`
- Client messages: `subscribe_room`, `typing_start`, `typing_stop`, `presence_update`
